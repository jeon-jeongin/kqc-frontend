# KQC 디자인 시스템 원칙

브랜드 가이드북(BS 01~10)과 kqchub.com의 톤을 제품 UI로 번역한 기준 문서입니다.
모든 시각적 결정은 이 문서와 `kqc-design-tokens.json`을 단일 소스로 합니다.

> 토큰 철학: **스케일은 메뉴판, 역할(role)이 주문 규칙이다.**
> 단계가 다양해도, 실제 화면에서는 아래 역할 정의대로만 조합해 사용한다.
> 역할에 없는 조합이 필요하면 임의로 만들지 말고 시스템에 역할을 추가하는 논의를 먼저 한다.

## 1. 운영 3원칙 (전 팀 합의 필요)

1. **디자인 시스템은 제약이다.** 시스템의 룰을 최대한 존중하고, 화면별 예외를 만들지 않는다.
2. **오픈소스(Mantine)에 끌려가지 않는다.** Mantine은 도구일 뿐, 기준은 KQC 토큰과 이 문서다.
3. **커스터마이징은 꼭 필요할 때만.** 디자이너 1인 + FE 1인이 논의하고 결과를 반드시 팀 채널에 공유한다. 화면 레벨 스타일 덮어쓰기 금지, 테마 레벨에서 해결한다.

## 2. 컬러 사용 규칙

### Main — Navy `#012169` (PANTONE 280C)
- 기본 버튼, 링크, 헤더, 강조 텍스트, 포커스 링은 모두 네이비.
- 진한 배경(navy.700+) 위 텍스트는 항상 white (가이드북 BS 08 Negative 규정).

### Point — Orange `#EA733D` (PANTONE 4012C) : 절제 규칙
포인트 컬러는 "여기가 제일 중요하다"는 신호. 신호가 많아지면 신호가 아니다.

**허용 (이 3가지뿐):**
1. 화면당 **최대 1개의 핵심 CTA**. 일반 버튼은 네이비.
2. **소면적 상태 인디케이터**: 활성 탭 언더바, 현재 스텝, 선택 마커, 뱃지 1종.
3. **데이터 시각화의 강조 시리즈 1개** (나머지는 navy/gray 계열).

**금지:**
- 본문 텍스트·텍스트 링크 (#EA733D는 흰 배경 대비 약 3:1 → 접근성 미달. 18px bold 이상 또는 non-text 요소만)
- 대면적 배경 (`bg.accentSubtle`만 화면당 1개 영역 이하 허용)
- 에러/경고 대체 — 에러는 red. 오렌지=강조, red=위험을 섞지 않는다.
- "예뻐 보여서" 쓰는 모든 경우 (아이콘 전체 채색, 보더 장식 등)

**리트머스 테스트:** 오렌지를 지웠을 때 잃는 정보가 없다면, 그 오렌지는 지운다.

### 보조
- Gray: 텍스트 위계(900/600), 배경(50/100), 보더(200/300). gray.400은 placeholder/disabled 전용(본문 대비 미달).
- 가이드북의 Purple/Teal 포인트는 우리 팀 제품에서 사용하지 않는다.

## 3. 타이포그래피 — 역할 기반 시스템

서체 3종: **Pretendard**(제품 UI 전체 — 제목 포함. 한/영 동일 설계라 혼용 시 이질감 없음),
**나눔스퀘어**(브랜딩 전용 — 로고 주변·히어로·마케팅 소재. 제품 UI 본문·제목에 사용 금지),
**JetBrains Mono**(코드·ID·정밀 수치). 굵기는 400/700 기본, 500은 미세 강조, 800은 display·숫자 강조 전용.
나눔스퀘어 Light는 화면 텍스트 사용 금지.

| 역할 | 크기/행간/자간 | 서체·굵기 | 용도 |
|---|---|---|---|
| display | 48 / 1.25 / -0.02em | 나눔스퀘어 800 | 히어로·랜딩(브랜딩 화면)만, 화면당 1곳 |
| h1 | 38 / 1.25 / -0.02em | Pretendard 700 | 페이지 제목 (모바일 30) |
| h2 | 30 / 1.25 / -0.01em | Pretendard 700 | 섹션 제목 (모바일 24) |
| h3 | 24 / 1.4 / -0.01em | Pretendard 700 | 서브 섹션 |
| h4 | 20 / 1.4 / -0.01em | Pretendard 700 | 카드·위젯 제목 |
| h5 | 16 / 1.4 | Pretendard 700 | 리스트 아이템·폼 그룹 제목 |
| bodyLg | 18 / 1.65 | Pretendard 400 | 리드문, 아티클 장문 |
| bodyMd | 16 / 1.5 | Pretendard 400 | 기본 UI 본문 |
| bodySm | 14 / 1.5 | Pretendard 400 | 보조 설명, 테이블 셀 |
| caption | 12 / 1.5 | Pretendard 400 | 타임스탬프, 헬퍼 텍스트 |
| overline | 11 / 1.4 / +0.06em | Pretendard 700 대문자 | 카테고리 라벨. 남용 금지 |
| code | 14 / 1.5 | Mono 400 | 코드, 큐빗/정밀 수치 |

**사용 규칙:**
- 한 화면에서 헤딩은 **최대 3단계**까지만 (display+h1 동시 사용 금지).
- 강조는 굵기(700)로, 크기 키우기로 하지 않는다.
- 역할 표에 없는 크기·행간 조합 금지. 반응형 축소는 display/h1/h2 세 역할만 정의된 값으로.
- 행간 원칙: 제목은 tight(1.25), UI는 normal(1.5), 장문은 relaxed(1.65). 임의 조정 금지.

## 4. 형태와 간격

### 간격 — 4px 그리드, 용도별 별칭 우선
스케일: 2·4·8·12·16·20·24·32·40·48·64·80·96. 화면 코드에서는 숫자 대신 **별칭**을 쓴다:

| 별칭 | 값 | 용도 |
|---|---|---|
| inlineXs / inlineSm | 4 / 8 | 아이콘-텍스트, 버튼 그룹 사이 |
| stackSm / stackMd / stackLg | 8 / 16 / 24 | 라벨-인풋, 폼 필드 사이, 카드 사이 |
| sectionSm / sectionLg | 48 / 80 | 앱 섹션 / 랜딩 섹션 사이 |
| inset.control / card / modal | 12 / 24 / 32 | 내부 패딩 기준 |

2와 20은 보정용(아이콘 정렬, 밀도 높은 테이블)으로만. 위 별칭으로 해결 안 되는 간격이 반복되면 별칭 추가를 논의한다.

**테마가 자동 강제하는 간격** (직접 gap을 안 써도 별칭이 적용됨):
`<Group>` 기본 gap = inlineSm(8) · `<Stack>` 기본 gap = stackMd(16) · 라벨↔인풋 = stackSm(8) · 인풋↔에러 = 4.
다른 간격이 필요하면 임의 숫자 대신 `gap="lg"`(=stackLg 24)처럼 테마 키로만 조정한다.

### Radius — 요소 성격별 고정
control(버튼·인풋) 6 / image 8 / card 12 / modal 16 / chip full.
브랜드 인상이 각져 있으므로(로고·PPT 템플릿) 16 초과 라운딩과 임의 값 금지. 같은 화면에서 같은 성격의 요소는 같은 radius.

### 그림자 — 레이어 위계 표현에만
xs(카드, 보더와 병행) / sm(드롭다운·팝오버) / md(모달) / lg(히어로·프로모션 카드 한정, navy 틴트).
정적 콘텐츠 장식용 그림자 금지. elevation은 "떠 있는 이유"가 있을 때만.

### 반응형 · 모션
- 브레이크포인트: 480 / 768 / 1024 / 1280 / 1440. Mantine responsive prop(`p={{ base, md }}`)으로만 분기.
- 모션: fast 120ms(hover) / normal 200ms(드롭다운) / slow 320ms(모달), easing standard. 장식성 애니메이션은 기본 지양, `prefers-reduced-motion` 존중.

## 5. 다크 모드 색 규칙

다크는 별도 팔레트를 그리지 않고 **스킴-인지 참조**로만 대응한다:

1. 본문은 색 지정 없음(자동), 보조 텍스트는 `c="dimmed"`. `gray.6` 같은 인덱스 지정 금지.
2. 브랜드색 텍스트·링크는 `c="navy"` (인덱스 없이). 라이트 700 / 다크 400으로 자동 전환된다.
3. 배경은 `light-dark(라이트값, 다크값)` 또는 Mantine 변수(`--mantine-color-body` 등)만.
4. 차트 시리즈 순서: `'navy'`(스킴 인지) → `'navy.2'` → `'gray.5'`. `navy.7` 고정 금지.
   `navy.4`도 시리즈 금지 — 다크에서 1번 시리즈가 400으로 전환돼 같은 색이 된다.
   accent(#EA733D)는 양쪽 스킴에서 유효, 차트당 1개.
5. `theme.other`의 hex 값들은 라이트 전용 — 다크 대응 화면에서 직접 사용 금지.
6. `light` variant(뱃지·버튼 배경)는 Mantine 9부터 반투명이 아닌 **불투명 단색**으로 계산된다.
   다크에서 자동으로 어두운 틴트 배경 + 밝은 텍스트가 되므로 별도 처리 금지.
   (예외: accent light는 라이트에서 브랜드 accentSubtle `#FDF1EA` 고정 — theme.ts에서 `light-dark()`로 분기)
7. 포커스 링은 라이트 navy.500 / 다크 navy.400 (`light-dark()`, global.css). 다크에서 500은 대비 미달.
8. 다크에서 밝아지는 보정(primaryShade dark:4)은 navy 전용이다. 시맨틱 색(red/green)의
   filled는 양쪽 스킴에서 원색(700) 고정 — theme.ts 리졸버가 강제하므로 `color="red"`만 쓰면 된다.

## 6. 접근성 기준선
- 본문 텍스트 대비 4.5:1 이상 (gray.600 이상만 본문 허용).
- 포커스 링 항상 표시: border.focus(navy.500) 2px.
- 색만으로 상태를 구분하지 않는다 (아이콘/텍스트 병행).
- 터치 타겟 최소 44×44px (모바일).

## 7. 콘솔 화면 패턴

우리 제품은 **콘솔형**(제어할 것이 많은 관리 화면)이다. 레퍼런스는 같은 유형에서 사용자가
많고 표준화가 잘된 것만: Claude 콘솔, GitHub Settings, Cursor, 업스테이지 콘솔.
(차트 화면은 토스증권 참고 — 유형이 다르면 레퍼런스도 다르다.)

1. **그루핑이 전부다.** 제어 항목은 중요도순 그룹으로 묶는다 (예: 일반 → 계정 → 사용량 → 기능).
   콘텐츠 안에서도 다시 그룹핑한다 — 기획(정보 설계)이 먼저다. 기능이 많아지면 그때 검색을 넣는다.
2. **뎁스 3단계 이하.** 위계: 사이드바 그룹 > 사이드바 > 콘텐츠 > 콘텐츠 서브 > 목적지.
   이 이상 깊어지면 구조를 다시 짠다.
3. **한 화면에 글자 크기 3개 이내**: 섹션 제목(h4) / 본문(md) / 설명(xs, dimmed).
4. **설정 행 = 설명 좌측, 컨트롤 우측.** 컨트롤은 세 가지만: 토글(on/off) /
   버튼(동작 단어 하나 — Open, Show, Export) / 드롭박스(선택지). Storybook `Patterns/설정 화면`이 참조 구현.
5. **아이콘이 애매하면 뺀다.** 아이콘은 설득이 되어야 하며, 텍스트보다 나을 때만 쓴다.
